# 🌱 枝 · 思维树 + 表达练习

一个手机浏览器就能用的网页，两件事拧成一件：

- **枝（想）**：把脑子里的碎片随手扔进来，AI 判断它该长在你思维树的哪个节点上，你只负责点「就挂这里」。
- **练习（说）**：录音 → 转写 → 按表达结构复盘 → 记下来。

它们不是两个 app。树里攒的观点可以一键生成表达稿、跳到练习页开口说；说完的复盘稿又能沉淀回树。
长期分析同时看这两边——你想得最多的主题，往往正是你讲不清楚的那个。

## 两个产品各自解决什么

**枝** 不解决"没地方记"，解决的是「我知道我有很多想法，但不知道怎么把它们组织起来」。
记录很容易，整理很难：判断它是什么 → 决定放哪 → 和旧知识建立关系 → 以后还找得到，
这四步以前全是用户自己干，现在交给 AI，用户只做一个决定：挂对了没有。

**练习** 不解决"讲得好听"，解决的是「在真实场景里没法条件反射地调用对应的表达结构」。
所以每次复盘都强制落到结构上——该用哪个结构、你的话填进槽位后哪几格是空的、下次开口第一句固定说什么。

## 六个页面

| 页面 | 干什么 |
| --- | --- |
| 枝 | 首页。文字或语音扔一条碎片进来 → AI 拆解 → 推荐挂载位置 → 你确认或换位置 |
| 树 | 整棵思维树、节点详情、按类型分组的碎片、追加内容、改挂载位置、AI 重新整理、帮我表达 |
| 练习 | 选场景和想练的结构（也可以让 AI 判断）→ 录音 → 自动转写（可手改）→ 出复盘 |
| 记录 | 灵感 / 方法原则 / 知识点 三类随手笔记（可一键扔进树），以及全部练习历史 |
| 结构 | 10 张结构卡，按"触发信号"排版，练的是看见场景就想起槽位 |
| 分析 | 把练习记录 + 笔记 + 思维树一起喂给模型，找反复犯的毛病、盲点、想过但从没讲过的主题 |

## 枝是怎么工作的

```
输入 → AI 理解 → AI 拆解 → 检索已有节点 → 推荐挂载位置 → 你确认 → 树更新
```

几条刻在 prompt 里的原则：

- **优先挂到已有节点**，让知识变厚，而不是每天制造一堆孤立的新笔记。
- **一条碎片 ≠ 一个新节点**。多数时候它只是某个节点里的一个「块」：核心观点 / 原因 / 案例 / 反例 / 数据 / 我的思考 / 相关观点 / 待验证问题。
  所以「生成 → 收敛」这个节点会慢慢长出 3 个案例、2 条原因，而不是散成 5 条笔记。
- **表面是树，底层是图**。一条碎片可以在挂到主节点的同时，横向关联到别的主题（相关 / 支持 / 矛盾 / 是…的例子 / 推导自）。
- **AI 建议，不替你决定**。推荐位置永远配一个「换个位置」，你可以选 AI 给的备选、自己挑节点、自己起名；
  节点随时能重命名、移动、删除，AI 整理出的分组你也可以直接改。

模型返回的挂载位置会先被前端洗一遍：引用了不存在的节点 id、给出十层深的新路径、块类型不在列表里，
都会被纠正或降级成「新建一个顶层节点」，不会把树写坏。

## 树和练习是怎么接上的

- 节点详情里的 **「帮我表达」**：观点版 / 面试版 / 小红书版 / 汇报版，每种模式直接复用结构库里的一个结构
  （PREP / STAR / 故事化 / 金字塔），只用你自己素材里的事实，素材不够就在「这个节点还缺」里明说，不替你编经历。
- 生成完点 **「去练习页开口说一遍」**：场景、结构、开口第一句都带过去，参考稿默认折叠——先自己讲，讲完再对。
- 复盘完点 **「把这段沉淀进思维树」**，说出来的东西反过来长回树上（碎片会标来源是「练习」还是「枝」）。
- 记录页的每条笔记也有「扔进思维树」。

## 最该盯的指标

分析页顶上那行 **挂载采纳率**：AI 推荐的位置里，你直接点「就挂这里」的比例。

它高，说明 AI 真的理解了你的思维结构，这个产品才成立；它低，说明推荐还不准——
这一版要证明的就只有这一件事，不是 DAU。

## 复盘会给你什么

- **目标结构 + 为什么是它**：这个场景该条件反射用哪个
- **槽位对照**：逐格显示你哪句填了、哪格是空的（引用你的原话）
- **四项评分**：结构 / 清晰 / 简洁 / 感染力
- **口头禅统计**：「然后 x6」这种
- **最该改的 1-3 处**：每处都给可以直接替换的说法
- **示范改写**：用目标结构重写你的内容，口语化，可以直接跟读
- **条件反射训练**：触发信号 + 开口第一句 + 一句口诀
- **再说一遍**：同一话题用目标结构重录，模型会对比两版的进步

## 怎么在手机上用

这不是一个现成的网站，是你自己跑的服务。要在手机上用，得先让它有个 **https 地址**——
浏览器只在 https 或 localhost 下才给麦克风权限，手机直连内网 IP（http）录音一定失败。

### 方案 A：部署一次，以后随时用（推荐）

用 [Render](https://render.com) 免费套餐，仓库里已经放好 `render.yaml`：

1. Render → New → Blueprint → 选这个仓库，它会自动读 `render.yaml`
2. 填两个环境变量：`OPENAI_API_KEY`（你的 key）、`ACCESS_CODE`（自己编一个访问码）
3. 部署完拿到 `https://xxx.onrender.com`，手机浏览器打开，输一次访问码

然后**添加到主屏幕**（iOS：Safari 分享 → 添加到主屏幕；Android Chrome：菜单 → 安装应用），
图标和全屏都配好了，用起来跟原生 app 一样。

> 免费套餐 15 分钟没人访问会休眠，下次打开要等 30 秒左右冷启动。

Railway、Fly.io、Zeabur 这类支持 Node 的平台同理，命令就是 `npm install` + `npm start`。

### 方案 B：先在电脑上跑，开个临时隧道试试（5 分钟）

```bash
npm install
cp .env.example .env    # 填上 OPENAI_API_KEY
npm start               # http://localhost:3000

# 另开一个终端，把本地服务映射成一个临时 https 地址
npx localtunnel --port 3000
```

手机打开它给的 `https://xxx.loca.lt` 就能录音。关掉终端地址就失效，适合先试试值不值得部署。

### 方案 C：只在电脑上用

`npm start` 之后开 `http://localhost:3000`，录音直接可用，不用任何隧道。

> 任何时候都可以不录音，直接在输入框手打文字复盘——转写只是省事，不是必需。

## 访问码

设了 `ACCESS_CODE` 之后，所有 AI 接口都要带对应的 header 才放行；前端第一次会弹一次输入框，
之后记在这台设备上。**部署到公网一定要设**，否则谁拿到链接都能花你的 OpenAI 额度。
本地不设就自动放行。

## 配置

| 环境变量 | 默认 | 说明 |
| --- | --- | --- |
| `OPENAI_API_KEY` | 必填 | 只放在服务端，不会进浏览器 |
| `OPENAI_BASE_URL` | `https://api.openai.com/v1` | 换 OpenAI 兼容网关时改这里 |
| `TRANSCRIBE_MODEL` | `gpt-4o-transcribe` | 也可以用 `whisper-1` |
| `REVIEW_MODEL` | `gpt-4o` | 复盘、长期分析、思维树的挂载推荐共用 |
| `ACCESS_CODE` | 空 | 公网部署必设；留空则不校验 |
| `PORT` | `3000` | |

## 数据存哪

全部在浏览器的 `localStorage`，没有数据库、没有账号，换设备或清缓存就没了。
分析页有「导出全部数据」按钮存 JSON 备份。录音本身不落盘——转写完就丢，只留文字。

| key | 存什么 |
| --- | --- |
| `xp.sessions` | 练习记录和复盘 |
| `xp.notes` | 随手笔记 |
| `xp.nodes` | 思维树节点，每个节点自带 `blocks[]` |
| `xp.rels` | 节点之间的横向关系（图的那一层） |
| `xp.mount` | 挂载推荐 / 采纳 / 改位置的次数，用来算采纳率 |

节点长这样：

```js
{ id, title, parentId, createdAt, updatedAt,
  blocks: [{ id, type: '案例', content, raw: '我当时的原话', source: '枝|练习|手动', createdAt }] }
```

## 代码结构

```
server.js       Express，六个接口，兼作 OpenAI 代理：
                  /api/transcribe  语音转文字（练习页和枝页共用）
                  /api/review      按结构复盘一段表达
                  /api/analyze     长期诊断（吃练习 + 笔记 + 思维树）
                  /api/ingest      碎片 → 拆解 + 挂载位置推荐  ← 枝的核心
                  /api/reorganize  一个主题攒多了，归纳成几个核心观点
                  /api/express     节点 → 可以直接开口说的稿子
structures.js   表达结构库（id / 触发信号 / 槽位 / 口诀），复盘 prompt 和结构卡共用同一份
tree.js         块类型、关系类型、表达模式（每种模式绑定一个表达结构）
public/         无构建的单页前端，PWA 图标和 manifest
  app.js          练习 / 笔记 / 分析 + 录音机和公共工具（挂在 window.XP 上）
  branch.js       思维树：挂载确认、树和节点详情、表达模式、AI 重新整理
render.yaml     Render 部署蓝图
```

要加新表达结构改 `structures.js`，要加新的块类型或表达模式改 `tree.js`，前后端同时生效。

## 已知取舍（这一版故意不做的）

- 没有账号和云端同步
- 没有主动回忆 / 定期复习（Phase 3 的事）
- 没有图片、网页剪藏、多人协作
- 没有语速 / 停顿 / 语气分析（转写只拿文字，要做得换带时间戳的接口）
- 树是纯列表渲染，没有可拖拽的图形视图
- 没有跨设备的长期趋势图，分析是每次现算的
