# 进销账

给医药销售用的进销 + 回款账本。链路：上游进货 → 付钱给上游 → 转卖给下游 → 下游回款（到公司账户或个人账户）→ 扣税 → 从公司提现。

## 怎么打开

**直接用（推荐）**：claude.ai 上发布好的页面 https://claude.ai/artifact/GkaFMssXvTfsCCHEFCgBTh ，手机、电脑登录 claude.ai 都能开。
账存在你 claude.ai 账号下的私有空间里，只有你自己看得到，换设备登录同一账号也在。
页面默认只有你能打开；要给别人用，在页面的分享菜单里加人，每个人看到的都是自己的那本账。

**自己部署**：`npm start` 后访问 `http://localhost:3000/ledger/`（部署后就是 `https://你的域名/ledger/`），
手机上可以「添加到主屏幕」。这种方式账只存在浏览器里，记得定期导出备份。不调任何 AI 接口，也不需要访问码。

第一次打开、账本还空着时会先放一套**示例数据**给你点着看，示例里的操作不保存；点「开始记自己的账」就切到你自己的空账本。

## 规则（都写在 `core.js` 里）

| 场景 | 怎么记 |
| --- | --- |
| 进货 | 上游厂家、品种、数量 × 进价。每笔进货 = 一笔欠上游的钱（应付）；成本按品种加权平均进价 |
| 记录多了怎么找 | 收付款页的回款记录、付款记录上有搜索框，按公司、药名、日期、备注搜 |
| 付上游（合并 / 部分） | 和回款同一套（也能筛）：一笔打款分到同一个上游的几批进货上，可以付清、付一部分、跳着挑；从个人账户或公司账户打出 |
| 销售 | 先选卖给哪家，再挑货：同一个厂家的同一个药合成一行（不管进了几批），厂家不同算两样货、分两行；行上直接填「卖几件」，默认先进先出，填了就自动展开（售价在展开区最上面，没定过售价的会标出来）；也可以点开看进价情况（每批哪天进、进价、剩几件），可以勾选整批或改件数。售价按「厂家 + 药」从价目表带出。一次可以挑好几样货，每样记一笔销售。每笔销售 = 一笔应收 |
| 价目表 | 每个厂家的每个药一个售价，卖给谁都一样，跟进价无关。第一次卖时填一次就记进去；某笔特殊价可以单改，默认不动价目表 |
| 回款（合并 / 部分） | 一笔到账分到同一个下游的几批货上：可以回清几批、某批只回一部分、回清几批再加一批的一部分，也可以跳着挑。默认从最早的开始分；每批有「全额 / 补剩下的 / 不回」快捷键，并实时显示这批这次回清还是回一部分、之后还欠多少。批次多于 3 批时可以按厂家、品种筛，或搜日期、备注；筛选只是藏起来，藏起来的批次分的钱照样算，筛选状态下「从最早的开始分」只分给显示出来的批次 |
| 回到个人账户 | 到账已经扣过税。按到账和每笔销售的税负，先进先出反推核销了多少应收，差额记为已扣税 |
| 回到公司账户 | 到账多少记多少，按同样的规则扣掉税，剩下的算你在公司的钱。公司什么时候交税不用管 |
| 从公司提现 | 你在公司的钱已经扣过税，提多少到手多少，最多提完为止 |
| 从公司付上游 | 从你在公司的钱里扣。例：回款 300 到公司（扣税 16，算你的 284）、付上游 200，还能提 84 |

### 下拉单（品种、上游公司、下游公司）

- 点输入框就列出下拉单里的名字，边打字边筛选；右边的箭头打开全部。名字旁边带一句当前情况（库存多少、谁欠谁多少），最近用过的排前面。
- 打了一个下拉单里没有的新名字，下面会出现「把『XX』加入下拉单，下次直接选」，默认勾上，不想加就取消。保存这笔账时才真的加进去。
- 记回款 / 付款时，下拉单里会补上所有有过往来的公司，欠钱的排前面。
- 设置页可以手动加、删；删掉不影响已经记的账。老账本第一次打开时，已经记过的名字会自动放进下拉单。

### 厂家

「厂家」就是进货时的上游公司。同一个药从不同厂家进，进价、库存、售价都分开算。
老销售没记厂家时：这个药只从一家进过货就认那家；从多家进过就按所有厂家的进货平均。

### 扣多少税

```
税 = 回款额 × 回款税点(默认 1%) + 差价 × 差价税率(默认 13%)
差价 = (售价 − 进价) × 件数

例：进价 1、售价 1.5、200 件，回款 300
    200×1.5×1% + 0.5×200×13% = 3 + 13 = 16，到手 284
```

- **按批次算成本**：同样的药每批进价不同。记销售时填件数默认先进先出分到各批，点开看进价可以自己调。
  成本 = 各批进价 × 各批件数，差价 = 销售额 − 成本。
- 销售会记住从哪几批出的货，之后再进货不影响它；改了某批的进价，从这批出货的销售跟着重算。
- 老销售没选过批次：先扣掉选了批次的销售，剩下的库存按先进先出分给它们（先用卖出那天之前进的货）。
- 库存不够或用到的批次被删了：差的几件先按平均进价算，并提醒；某批记的卖出比进的多也会提醒。
- 价目表里的「每件差价 / 每件扣税」按下一批要出的货（先进先出）的进价算。
- 所以每笔销售的税负不同：上面这笔是 16/300 ≈ 5.33%，差价大的货税负更高。
- 合并回款时，核销到哪笔销售就按哪笔的税负算；部分回款按比例算（回一半，扣一半的税）。
- 回到公司的钱也按同样规则扣：核销到哪笔销售就按哪笔的税负算。
  回款里没对上任何销售的部分，按这个下游销售的平均税负估。
- 卖亏了（售价低于进价）差价按 0 算，只扣回款税点那部分。
- 两个税率在「设置」里改，改完历史账目全部按新税率重算。

## 为什么删改不会把账弄乱

只存原始单据（进货、销售、回款、扣税、提现），余额和税每次都按日期顺序重放算出来。
删掉一笔回款，后面的扣税金额自动变；要是后面的提现因此不够了，会在顶部标红提示。
两个账户都只记「你的钱」：

- 公司账户 = 回到公司的钱（按规则扣完税）− 从公司付上游的 − 提到个人的。提现超过它会被拦下；付上游超过它照记，但会提醒「先占用了公司的钱」。
个人账户 = 回到个人的钱 + 从公司提出来的 − 从个人付给上游的（可以是负数，表示先垫了钱）。

## 数据存哪（`store.js`）

| 在哪打开 | 存在哪 |
| --- | --- |
| claude.ai 页面 | 账号私有空间 `data/users/<你的id>/ledger`，本机 `localStorage` 留一份缓存 |
| 自己部署的服务 | 只存浏览器 `localStorage` 的 `ledger.v1` |

云端单个文档上限 256 KiB，整本账按块切开存：先写新块，再改指针，最后删旧块，中途断掉也不会坏。
另一台设备改了账，这边会自动刷新。设置页可以导出 JSON 备份、导出销售明细 CSV。
