# 进销账

给医药销售用的进销 + 回款账本。链路：上游进货 → 付钱给上游 → 转卖给下游 → 下游回款（到公司账户或个人账户）→ 扣税 → 从公司提现。

## 怎么打开

有三种用法，同一套页面，打开的地方不同：

| 用法 | 适合 | 账存在哪 |
| --- | --- | --- |
| **进销账服务器**（`ledger-server.js`） | 几个人一起记一本账，每个人用手机号注册登录，不需要 claude.ai 账号 | 服务器上一个 SQLite 文件；每台设备上也存一份，没网也能看、能记 |
| claude.ai 页面 https://claude.ai/artifact/GkaFMssXvTfsCCHEFCgBTh | 自己一个人用，有 claude.ai 账号 | 你 claude.ai 账号下的私有空间 |
| 别的地方（本地文件、只有静态页面的服务） | 试试看 | 只存在这个浏览器里 |

第一次打开、账本还空着时会先放一套**示例数据**给你点着看，示例里的操作不保存；点「开始记自己的账」就切到你自己的空账本。

## 几个人一起记一本账（服务器版）

- **注册登录**：手机号 + 密码。注册时没填邀请码，就给你建一本自己的账本，你是「老板」。
- **邀请同事**：设置 → 成员 → 邀请同事，选好身份，生成一个链接（7 天内有效、只能用一次）发给他。
  他打开链接注册（已有账号就登录）就进了这本账。也可以注册时手动填 8 位邀请码。
- **两种身份**（`roles.js`）：

  | 身份 | 能看 | 能记 / 能改 |
  | --- | --- | --- |
  | 全部权限（建账本的人显示为「老板」） | 整本账 | 全部；能邀请、移出成员 |
  | 只记收付款 | 只有自己记的回款、付款，加上下游公司、上游厂家的名字（选公司要用，不带金额） | 只能记回款、付上游；只能改、删自己记的 |

  只有老板能把别人设成「全部权限」；全部权限的人能邀请「只记收付款」的人。老板不能被改、不能被移出。
- **看不到的就不发**：只记收付款的人，服务器只把他自己记的回款、付款发给他（连核销到哪几批货也不发），
  销售、进货、库存、价目表、两个账户的钱、税、别人记的，都不会到他手机上。他的页面只有「收付款」「设置」两页。
- **他记的回款 / 付款怎么核销**：他看不到销售和进货，所以由服务器按最早的先核销（回到个人账户的，按税负反推核销了多少应收）。
  老板那边能看到、也能改；之后他只改备注不会动老板调过的核销，改了金额、公司、账户或日期会重新按最早的先核销。
- **身份改了**：服务器上马上生效。他下次打开时，手机上的账会清掉，按新的身份重新下载。
  所以从全部权限降成只记收付款的人，降之前已经下载到他手机上的账，要等他下次联网打开才清掉。
- **权限在服务器上检查**：页面上不显示不能用的功能；就算绕过页面直接调接口，服务器也不收没权限的单据、不发不该看的数据。
- **每笔是谁记的**：列表里会标出来；全部权限的人在「操作记录」里能看到谁什么时候记了、改了、删了哪一笔。
- **忘了密码**：全部权限的人在成员里点「重置密码」，给一个临时密码。老板自己忘了，在服务器上跑
  `node ledger-admin.js reset-password 手机号`。为了安全，同时在别人账本里的人，只能让他自己改，或者在服务器上重置。
- **没网**：每一笔先存在手机上（IndexedDB），联网后自动传上去。装到手机桌面以后，没网也能打开。
- **两个人同时改同一笔**：按传到服务器的先后，后到的算。

### 装到手机上

页面是 PWA：用 HTTPS 打开以后，设置页有「装到手机桌面」。

- 安卓：浏览器菜单里选「添加到主屏幕」或「安装应用」。
- iPhone：用 Safari 打开，点「分享」，选「添加到主屏幕」。
- 在微信里打开的：先点右上角，选「在浏览器打开」。

装好以后像 app 一样从桌面图标打开，全屏、没有地址栏。

### 部署

要一台大家都能访问的服务器 + 一个域名 + HTTPS（装到桌面、离线打开都要求 HTTPS）。

```bash
# 服务器上（Node.js 22.5 以上）
git clone <这个仓库> /srv/jinxiaozhang && cd /srv/jinxiaozhang
npm ci --omit=dev
DATA_DIR=/srv/jinxiaozhang/data PORT=3100 npm run ledger    # 建议用 systemd / pm2 守护
# HTTPS：装 Caddy，按 deploy/Caddyfile 改成你的域名，它会自动申请免费证书
```

也可以用 Docker：`docker build -f ledger.Dockerfile -t jinxiaozhang .`，然后
`docker run -d -p 3100:3100 -v jinxiaozhang-data:/data --restart unless-stopped jinxiaozhang`。

- **数据**全在 `DATA_DIR/ledger.db` 一个文件里，一定要放在不会被清掉的磁盘上（很多免费托管平台重启就清盘，不能用）。
- **备份**：`node ledger-admin.js backup`，不停服务导出一份完整的数据库。每天定时跑见 `deploy/backup.cron`。
- **看有哪些账号**：`node ledger-admin.js users`。
- 服务器放在国内、用国内域名，要先做 ICP 备案；放在香港 / 海外不用备案，但国内打开可能慢一些。

## 规则（都写在 `core.js` 里）

| 场景 | 怎么记 |
| --- | --- |
| 进货 | 上游厂家、品种、数量 × 进价。每笔进货 = 一笔欠上游的钱（应付）；成本按品种加权平均进价 |
| 记录多了怎么找 | 收付款页的回款记录、付款记录上有搜索框，按公司、药名、日期、备注搜 |
| 付上游（合并 / 部分） | 和回款同一套（也能筛）：一笔打款分到同一个上游的几批进货上，可以付清、付一部分、跳着挑；从个人账户或公司账户打出 |
| 销售 | 先选卖给哪家，再挑货：同一个厂家的同一个药合成一行（不管进了几批），厂家不同算两样货、分两行；行上直接填「卖几件」，默认先进先出，填了就自动展开（售价在展开区最上面，没定过售价的会标出来）；也可以点开看进价情况（每批哪天进、进价、剩几件），可以勾选整批或改件数。售价按「厂家 + 药」从价目表带出。一次可以挑好几样货，每样记一笔销售。每笔销售 = 一笔应收 |
| 价目表 | 每个厂家的每个药一个售价，卖给谁都一样，跟进价无关。第一次卖时填一次就记进去。记销售时改了已定过的售价，会提醒「改价了」并让你选「只这笔」还是「以后都按这个价（更新价目表）」；没选就点保存，会弹窗再问一次 |
| 回款（合并 / 部分） | 一笔到账分到同一个下游的几批货上：可以回清几批、某批只回一部分、回清几批再加一批的一部分，也可以跳着挑。默认从最早的开始分；每批有「全额 / 补剩下的 / 不回」快捷键，并实时显示这批这次回清还是回一部分、之后还欠多少。批次多于 3 批时可以按厂家、品种筛，或搜日期、备注；筛选只是藏起来，藏起来的批次分的钱照样算，筛选状态下「从最早的开始分」只分给显示出来的批次 |
| 回到个人账户 | 到账已经扣过税。按到账和每笔销售的税负，先进先出反推核销了多少应收，差额记为已扣税 |
| 回到公司账户 | 到账多少记多少，按同样的规则扣掉税，剩下的算你在公司的钱。公司什么时候交税不用管 |
| 从公司提现 | 你在公司的钱已经扣过税，提多少到手多少，最多提完为止 |
| 从公司付上游 | 从你在公司的钱里扣。例：回款 300 到公司（扣税 16，算你的 284）、付上游 200，还能提 84 |

### 下拉单（品种、上游公司、下游公司）

- 点输入框就列出下拉单里的名字，边打字边筛选；右边的箭头打开全部。名字旁边带一句当前情况（库存多少、谁欠谁多少），最近用过的排前面。
- 打了一个下拉单里没有的新名字，下面会出现「把『XX』加入下拉单，下次直接选」，默认勾上，不想加就取消。保存这笔账时才真的加进去。
- 记回款 / 付款时，下拉单里会补上所有有过往来的公司，欠钱的排前面。
- 设置页可以手动加、删；删掉不影响已经记的账。老账本第一次打开时，已经记过的名字会自动放进下拉单。

### 厂家

「厂家」就是进货时的上游公司。同一个药从不同厂家进，进价、库存、售价都分开算。
老销售没记厂家时：这个药只从一家进过货就认那家；从多家进过就按所有厂家的进货平均。

### 扣多少税

```
税 = 回款额 × 回款税点(默认 1%) + 差价 × 差价税率(默认 13%)
差价 = (售价 − 进价) × 件数

例：进价 1、售价 1.5、200 件，回款 300
    200×1.5×1% + 0.5×200×13% = 3 + 13 = 16，到手 284
```

- **按批次算成本**：同样的药每批进价不同。记销售时填件数默认先进先出分到各批，点开看进价可以自己调。
  成本 = 各批进价 × 各批件数，差价 = 销售额 − 成本。
- 销售会记住从哪几批出的货，之后再进货不影响它；改了某批的进价，从这批出货的销售跟着重算。
- 老销售没选过批次：先扣掉选了批次的销售，剩下的库存按先进先出分给它们（先用卖出那天之前进的货）。
- 库存不够或用到的批次被删了：差的几件先按平均进价算，并提醒；某批记的卖出比进的多也会提醒。
- 价目表里的「每件差价 / 每件扣税」按下一批要出的货（先进先出）的进价算。
- 所以每笔销售的税负不同：上面这笔是 16/300 ≈ 5.33%，差价大的货税负更高。
- 合并回款时，核销到哪笔销售就按哪笔的税负算；部分回款按比例算（回一半，扣一半的税）。
- 回到公司的钱也按同样规则扣：核销到哪笔销售就按哪笔的税负算。
  回款里没对上任何销售的部分，按这个下游销售的平均税负估。
- 卖亏了（售价低于进价）差价按 0 算，只扣回款税点那部分。
- 两个税率在「设置」里改，改完历史账目全部按新税率重算。

## 为什么删改不会把账弄乱

只存原始单据（进货、销售、回款、扣税、提现），余额和税每次都按日期顺序重放算出来。
删掉一笔回款，后面的扣税金额自动变；要是后面的提现因此不够了，会在顶部标红提示。
两个账户都只记「你的钱」：

- 公司账户 = 回到公司的钱（按规则扣完税）− 从公司付上游的 − 提到个人的。提现超过它会被拦下；付上游超过它照记，但会提醒「先占用了公司的钱」。
个人账户 = 回到个人的钱 + 从公司提出来的 − 从个人付给上游的（可以是负数，表示先垫了钱）。

## 数据存哪

**服务器版**（`server/ledger/`、`remote.js`、`sync.js`）：服务器是准，每一笔在服务器上有一个版本号。
手机上记的先存本机，再传给服务器（服务器检查权限，按到达先后），然后把别人改的拉下来。
拉下来的变化碰到本机还没传上去的同一笔，先留本机的，下次传上去。
删掉的在服务器上留一条删除记录，别的设备才知道要删。

**claude.ai 页面**（`store.js`）：本机 `localStorage` 为主，联网后和账号私有空间 `data/users/<你的id>/ledger2` 同步。

每一笔先存本机：没网、云端还没连上时照样能记，联网后自动传上去。

同步按「每一笔」合并，不是整本覆盖：
- 每一笔都带一个修改时间。同一笔在两台设备上都改过时，留后改的那次。
- 删掉的留一条删除记录，别的设备上的旧数据不会把它带回来。清空、导入也一样，会同步到其他设备。
- 云端按「单据类型 + 月份」分块存（价目表、设置、下拉单一块，删除记录一块），每块有内容指纹。
- 每次同步只下载别的设备改过的块，只上传自己变了的块，记一笔只传一个月份。
- 同步时拿一个短锁，同一时间只有一台设备在写。所有块传完才改目录，中途断掉也不会坏。

旧版（`ledger`，整本账一起存）第一次同步时自动合并进来，原数据保留不删。

**只存本机**：浏览器 `localStorage` 的 `ledger.v1`。用服务器版登录后，老板的新账本还空着时会问要不要把这些放进去。

设置页可以导出 JSON 备份、导出销售明细 CSV；老板可以导入 JSON（会覆盖整本账）。

## 文件

| 文件 | 干什么 |
| --- | --- |
| `core.js` | 算账：应收、应付、核销、扣税、两个账户的余额，纯函数 |
| `roles.js` | 身份和权限，页面和服务器共用 |
| `sync.js` | 服务器版的同步规则：哪些还没传、拉下来的怎么并进来，纯函数 |
| `remote.js` | 服务器版：调接口、本机缓存（IndexedDB）、自动同步 |
| `store.js` | claude.ai 页面版：存取 claude.ai 云端 / 本机 |
| `boot.js` | 入口：判断是哪种用法，要不要先登录 |
| `auth-ui.js` | 登录、注册、用邀请码加入 |
| `app.js` | 界面 |
| `sw.js` | 装到桌面后没网也能打开 |
| `index.html` | 服务器版 / 自己部署的入口 |
| `artifact.html` | 发布到 claude.ai 的入口（平台会自动包上 doctype/head/body） |
| `../../ledger-server.js` | 服务器入口；接口在 `../../server/ledger/`（`api.js` 接口和权限检查、`auth.js` 密码和登录、`db.js` 数据库） |
| `../../ledger-admin.js` | 服务器上的维护命令：看账号、重置密码、备份 |
